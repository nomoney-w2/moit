## Background

현재 구현과 Figma 시안 사이에서 발견된 4가지 세부 불일치를 한 번에 정리한다. 모두 모임 생성·투표 결과 화면 폴리시 성격이며, 사용자에게는 "당연히 이래야 하는데 안 되는" 자잘한 마찰을 제거하는 작업이다.

- **시간 라벨 자릿수**: 시간 슬롯 그리드의 시 라벨이 한 자리(`0`, `1`, …, `9`)와 두 자리(`10`, …, `23`)가 섞여 좌측 라벨 열의 시각적 정렬이 깨진다.
- **모임명 placeholder vs 입력 검증 모순**: 모임명 입력의 placeholder는 `멋쟁이들 모임`처럼 **공백을 포함**한 문구이지만, 실제로 사용자가 동일한 문구를 직접 입력하려고 하면 "한글, 영문, 숫자만 입력 가능해요" 에러로 막힌다.
- **모임장 이름에 공백 입력 불가**: 모임장 이름도 한글·영문만 허용해 공백을 입력할 수 없다.
- **참여자 이름 등록/수정에도 동일 제약**: 동일 정규식이 참여자 이름 등록(`useParticipantRegisterName`) 및 수정/검색(`useParticipantEditName`) 흐름에도 적용되어, 공백을 포함한 이름은 등록·검색이 불가능하다.
- **결과 페이지 뷰 토글 아이콘 불일치**: 투표 결과 페이지의 그리드/캘린더 뷰 전환 토글 thumb 안의 아이콘이 Figma 시안과 다르다.

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 모임명·모임장·참여자 이름 입력에 공백 허용 (Priority: P1)

호스트와 참여자 모두가 "자정 테스트", "다같이 모여요", "김 길동" 처럼 단어 사이에 공백이 들어가는 자연스러운 한국어 이름을 입력할 수 있어야 한다. 현재는 공백을 누르면 에러 메시지가 떠 입력이 차단되며, 이는 모임명 placeholder(`멋쟁이들 모임`)와도 모순된다.

본 규정은 **이름 성격의 모든 입력 필드**에 동일하게 적용된다:

1. 모임 생성 — 모임장 이름 / 모임명 (`useMeetCreateForm`)
2. 참여자 이름 등록 — 처음 투표 참여 시 이름 입력 (`useParticipantRegisterName`)
3. 참여자 이름 수정 — 본인 투표 수정 시 이름 검색 입력 (`useParticipantEditName`)

**Why this priority**: placeholder가 가리키는 기본값을 사용자가 그대로 따라 칠 수 없다는 것은 입력 신뢰성에 직접적인 손상을 준다. 4개 이슈 중 가장 사용자가 즉시 마주치는 마찰이며, 다른 폴리시 이슈(시간 라벨·아이콘)와 달리 실제로 흐름을 막는다. 또한 참여자 이름이 공백을 포함한 형태로 호스트 측에 등록되어 있다면, 참여자가 본인 이름으로 수정하려 들어가도 공백을 칠 수 없어 검색 자체가 막힌다.

**Independent Test**: 모임 생성 페이지(모임장·모임명), 참여자 이름 등록 페이지, 참여자 이름 수정 페이지 각각에서 공백을 포함한 문자열(예: `김 길동`, `자정 테스트`)을 직접 타이핑한다. 모든 필드에서 에러 없이 입력값이 유지되고 다음 단계 CTA가 활성화되면 통과.

**Acceptance Scenarios**:

1. **Given** 모임 생성 페이지에서 모임장 이름이 비어 있을 때, **When** 사용자가 `김 길동`을 키보드로 입력하면, **Then** 입력 필드에 `김 길동`이 그대로 유지되고 "한글, 영문만 입력 가능해요" 에러가 나타나지 않으며, 모임장 입력 조건만 충족되면 CTA가 활성화된다.
2. **Given** 모임명 placeholder가 `멋쟁이들 모임`으로 보이는 상태에서, **When** 사용자가 동일하게 `멋쟁이들 모임`을 타이핑하면, **Then** 입력값은 그대로 유지되고 "한글, 영문, 숫자만 입력 가능해요" 에러가 나타나지 않는다.
3. **Given** 모임명 입력 필드에 공백 포함 값이 들어 있을 때, **When** 사용자가 CTA `날짜 선택하기` 를 누르면, **Then** 그 값(공백 포함, 앞뒤 trim 적용)이 다음 단계로 그대로 전달된다.
4. **Given** 모임장 입력 필드가 공백만(`"   "`)으로 채워졌을 때, **When** 사용자가 키 입력을 마치면, **Then** CTA는 비활성 상태가 되고 모임장 필드 하단에 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 가 표시된다 (모임명·참여자 이름과 동일한 정책).
5. **Given** 모임명 입력 필드가 완전히 비어 있을 때, **When** 사용자가 CTA를 누르면, **Then** 기존 동작 그대로 현재 표시 중인 placeholder 문구가 최종 모임명으로 사용된다 (`is_autofilled=true`).
6. **Given** 모임명 입력 필드에 공백만(`" "`, `"   "` 등)이 입력된 상태일 때, **When** 사용자가 키 입력을 마치면, **Then** CTA는 비활성 상태이고 모임명 필드 하단에 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 가 표시되며, placeholder 자동 대체는 일어나지 않는다.
7. **Given** 참여자 이름 등록 페이지(`/meet/[meetingId]/register`)에서, **When** 사용자가 `김 길동` 을 입력하면, **Then** 에러 없이 유지되고 CTA가 활성화되어 다음 단계(날짜 선택)로 진행 가능하다.
8. **Given** 참여자 이름 등록 페이지에서, **When** 사용자가 공백만(`"   "`) 입력하면, **Then** CTA는 비활성 상태이고 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 가 표시된다.
9. **Given** 참여자 이름 수정 페이지(`/meet/[meetingId]/edit`)에서 호스트가 본인 이름을 `김 길동` 으로 투표했을 때, **When** 사용자가 `김 길동` 을 입력하면, **Then** 에러 없이 유지되고 CTA 클릭 시 정상적으로 참여 이력 확인 API가 호출된다.
10. **Given** 참여자 이름 수정 페이지에서, **When** 사용자가 공백만 입력하면, **Then** CTA는 비활성 상태이고 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 가 표시된다.

### User Story 2 - 시간 슬롯 행 라벨 두 자리수 표시 (Priority: P2)

투표 결과 페이지(`HeatmapGrid`)와 참여자 시간 슬롯 입력 페이지(`TimeSlotGrid`)의 좌측 시간 라벨이 항상 두 자리(`00`, `01`, …, `09`, `10`, …, `23`)로 표시되어 좌측 정렬이 시각적으로 가지런해야 한다.

**Why this priority**: 미관/시안 일치 이슈이며 기능 진행을 막지는 않지만, 새벽 시간대(0~9시) 라벨이 한 자리로 표시되어 좌측 라벨 열이 들쭉날쭉해 보이는 폴리시 결함이 일관되게 발생한다.

**Independent Test**: 모임의 시간 범위에 0~9시 사이의 시간(예: `00:00 ~ 06:00`)이 포함되도록 만들어 시간 슬롯 그리드/히트맵 그리드를 띄우고, 좌측 라벨이 `00`, `01`, `02`, `03`, `04`, `05` 로 두 자리 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 시간 범위가 `00:00 ~ 23:00`인 모임의 결과 히트맵 그리드가 표시될 때, **When** 사용자가 좌측 시간 라벨 열을 확인하면, **Then** 모든 라벨이 `00`, `01`, …, `09`, `10`, …, `22` 와 같이 두 자리수로 표시된다.
2. **Given** 시간 범위가 `01:30 ~ 04:30`인 모임의 참여자 시간 슬롯 그리드가 표시될 때, **When** 사용자가 좌측 시간 라벨 열을 확인하면, **Then** `01`, `02`, `03`, `04` 가 모두 두 자리수로 표시된다.
3. **Given** 시간 범위가 `10:00 ~ 18:00`인 경우(두 자리만 포함), **When** 사용자가 좌측 시간 라벨 열을 확인하면, **Then** 기존과 동일하게 `10`, `11`, …, `17` 로 표시된다 (회귀 없음).

### User Story 3 - 결과 페이지 뷰 토글 아이콘 시안 일치 (Priority: P3)

투표 결과 페이지 우상단의 그리드/캘린더 뷰 전환 토글의 thumb 안에 들어가는 아이콘이 Figma 시안과 일치해야 한다.

**Why this priority**: 시각 폴리시 이슈로 기능에는 영향을 주지 않으며, Figma sync 차원에서 처리한다.

**Independent Test**: 결과 페이지를 띄워 토글 두 상태(그리드 상태/캘린더 상태) 각각에서 thumb 안 아이콘이 Figma 시안 노드 [3639:20842](https://www.figma.com/design/3QGpLOWvN7ZvBpYhqqzcJ4/moit-UI-Design?node-id=3639-20842&m=dev), [3650:30362](https://www.figma.com/design/3QGpLOWvN7ZvBpYhqqzcJ4/moit-UI-Design?node-id=3650-30362&m=dev) 와 픽셀 단위로 가지런한지 확인.

**Acceptance Scenarios**:

1. **Given** 결과 페이지가 그리드 뷰 상태(`mode === 'grid'`)일 때, **When** 토글이 좌측 thumb 위치에 있고 thumb 내부 아이콘을 확인하면, **Then** 아이콘이 Figma 시안의 좌측 상태 아이콘과 일치한다.
2. **Given** 결과 페이지가 캘린더 뷰 상태(`mode === 'list'`)일 때, **When** 토글이 우측 thumb 위치에 있고 thumb 내부 아이콘을 확인하면, **Then** 아이콘이 Figma 시안의 우측 상태 아이콘과 일치한다.

### Edge Cases

- **모든 이름 필드 공백-only 입력 일관 정책**: 모임장 / 모임명 / 참여자 이름(등록·수정) 4 필드 모두 `value !== '' && value.trim() === ''` 인 상태에서는 CTA 비활성 + 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 가 표시된다. 4 흐름 간 에러 표기 비대칭이 없다.
- **모임명 완전 빈 입력 vs 공백만 입력 구분**: 모임명 필드가 **완전히 비어 있으면**(`""`) 기존처럼 placeholder 문구가 최종값으로 자동 대체된다. 그러나 사용자가 **공백 키를 한 번이라도 눌러** 필드가 공백만으로 채워진 상태(`" "`, `"   "` 등)에서는 placeholder 대체가 발생하지 않고 CTA가 비활성 + 에러 메시지가 노출된다. "공백을 친 것"은 의도된 입력으로 해석한다.
- **모임명/모임장 앞·뒤 공백**: 입력 도중에는 자유롭게 허용한다. 제출 시(CTA 클릭) 다음 단계로 넘기는 값은 `.trim()` 적용된 형태로 전달한다(기존 동작과 동일).
- **모임명/모임장 길이 제한**: 공백 문자 포함 10자 제한(`maxLength=10`)을 그대로 유지한다 — 공백도 1자로 계산된다.
- **시간 라벨 24시 표기**: 현재 그리드 로직상 `h < endHour` 로 24는 라벨 행으로 그려지지 않는다. 본 변경은 표시 포맷만 바꾸므로 동일하게 유지된다.
- **시간 라벨 좌측 컬럼 폭**: 두 자리수로 통일되면 폭(`TIME_COL_W = 40`)이 충분하므로 레이아웃이 흔들리지 않는다.
- **토글 아이콘 컬러 토큰**: 현재 구현은 `#3C7EFA` 하드코딩. 새 아이콘 자산도 동일 톤(또는 시안에 명시된 토큰)을 사용한다.

## Requirements _(mandatory)_

### Functional Requirements

#### 입력 검증 (이름 성격 필드 공백 허용)

본 절의 규정은 **모임 생성(모임장·모임명) + 참여자 이름 등록 + 참여자 이름 수정** 세 흐름에 동일하게 적용된다.

- **FR-001**: 시스템은 모임장 이름 입력 필드에서 **반각 공백 문자(` `, U+0020)** 를 허용해야 한다 — 한글/영문에 더해 공백을 입력해도 "한글, 영문만 입력 가능해요" 에러를 표시하지 않는다.
- **FR-002**: 시스템은 모임명 입력 필드에서 **반각 공백 문자(` `)** 를 허용해야 한다 — 한글/영문/숫자에 더해 공백을 입력해도 "한글, 영문, 숫자만 입력 가능해요" 에러를 표시하지 않는다.
- **FR-002a**: 시스템은 참여자 이름 **등록** 입력 필드(`useParticipantRegisterName`)에서 반각 공백을 허용해야 한다 — 기존 정규식 `^[ㄱ-힣a-zA-Z]*$` 를 `^[ㄱ-힣a-zA-Z ]*$` 로 확장.
- **FR-002b**: 시스템은 참여자 이름 **수정/검색** 입력 필드(`useParticipantEditName`)에서 반각 공백을 허용해야 한다 — 등록과 동일한 정규식 확장.
- **FR-003**: 시스템은 모임장 이름의 공백을 트림한 결과가 빈 문자열이면 CTA를 비활성 상태로 유지해야 한다 (기존 `hostName.trim() !== ''` 조건 유지).
- **FR-003-host-ws**: 시스템은 모임장 필드에 **공백 문자만 입력된 상태**(`hostName !== '' && hostName.trim() === ''`)에서는 CTA를 비활성 상태로 유지하고 모임장 필드 하단에 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 를 표시해야 한다 (4 필드 일관 정책).
- **FR-003a**: 시스템은 모임명 필드가 **완전히 비어 있을 때만**(`meetingName === ''`) placeholder 문구를 최종 모임명으로 자동 대체해야 한다 — 기존 `is_autofilled=true` 동작 그대로.
- **FR-003b**: 시스템은 모임명 필드에 **공백 문자만 입력된 상태**(`meetingName !== '' && meetingName.trim() === ''`)에서는 CTA를 비활성 상태로 유지하고, 모임명 필드 하단에 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 를 표시해야 한다. 이 상태에서는 placeholder 자동 대체가 발생하지 않는다.
- **FR-003c**: 시스템은 참여자 이름 등록/수정 입력 필드에 **공백 문자만 입력된 상태**(`name !== '' && name.trim() === ''`)에서는 `isValidInput`(CTA)을 비활성 상태로 유지하고 인라인 에러 메시지 `"공백만 입력할 수 없어요"` 를 표시해야 한다. 단순히 길이만 보던 기존 `isValidInput: name.length > 0 && !errorDetails.isError` 조건을 `name.trim().length > 0 && !errorDetails.isError` 로 강화한다.
- **FR-004**: 시스템은 CTA 클릭 시 다음 단계로 넘기는 모든 이름 값(모임장/모임명/참여자)에 `.trim()`을 적용해 앞뒤 공백을 제거해야 한다 — 단어 사이 공백은 보존한다.
- **FR-005**: 시스템은 placeholder로 보여주는 기본 모임명 후보(`멋쟁이들 모임`, `우리들의 약속`, `즐거운 만남`, `행복한 하루`, `설레는 모임`) 와 동일한 문자열을 사용자가 직접 입력하더라도 에러 메시지가 표시되지 않아야 한다 (placeholder ↔ 입력 검증 일관성).
- **FR-006**: 모임명/모임장/참여자 이름 길이 제한 `maxLength=10`은 공백 포함하여 그대로 유지되어야 한다.
- **FR-007**: 입력 정규식 외 다른 제약(특수문자 차단 등)은 기존과 동일하게 유지되어야 한다 — 예: `김!길동` 같은 특수문자 입력은 여전히 에러를 표시한다.

#### 시간 슬롯 행 라벨 두 자리수

- **FR-008**: 참여자 시간 슬롯 그리드(`TimeSlotGrid`)의 좌측 시 라벨은 항상 두 자리 십진수로 표시되어야 한다 (예: `0` → `00`, `9` → `09`, `13` → `13`).
- **FR-009**: 투표 결과 히트맵 그리드(`HeatmapGrid`)의 좌측 시 라벨은 항상 두 자리 십진수로 표시되어야 한다.

- Q: 결과 페이지 토글 아이콘이 Figma와 정확히 어떤 모양인지 명세 단계에서 추가 설명이 필요한가요? → A: Figma 노드 참조만으로 충분 — 구현 단계에서 Figma MCP로 자산을 추출·재구현해 현재 SVG 마크업을 교체한다.

## Assumptions

- 공백 허용 범위는 **반각 스페이스(U+0020)** 만을 의미한다 — 탭, 줄바꿈, 전각 공백, NBSP 등은 별도 고려 대상이 아니며 기본 정규식에서 자연스럽게 차단된다.
- 모임장 이름은 기존 정책대로 **숫자는 허용하지 않는다** (`[ㄱ-힣a-zA-Z]` + 공백). 모임명만 숫자 허용 (`[ㄱ-힣a-zA-Z0-9]` + 공백).
- placeholder 후보 목록(`멋쟁이들 모임` 등)은 변경하지 않는다 — placeholder를 바꿔서 모순을 해소하는 것이 아니라 **검증을 완화**해서 모순을 해소한다.
- 결과 페이지 토글 아이콘은 Figma 시안 자산을 SVG로 추출/재구현해 `ViewToggle` 의 현재 SVG 마크업을 교체하는 식으로 처리한다. 추출은 구현 단계에서 진행한다.
- 본 작업은 클라이언트 UI/검증 폴리시이며, 백엔드 스키마·API·저장 형식 변경은 없다.

## Out of Scope

- placeholder 후보 목록 추가/수정
- 모임장 이름에 숫자 허용 (기존 정책 유지)
- 전각 공백(U+3000), NBSP(U+00A0) 등 비반각 공백 처리
- 토글 자체의 동작·색상·크기 변경 (아이콘 교체만)
- 시간 라벨 표시 외의 시간 그리드 동작 변경
