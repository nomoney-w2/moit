## 배경

`VoteRankCardList`는 투표 결과를 득표 순으로 정렬하여 카드 형태로 표시하는 컴포넌트이다. 각 카드에는 순위 뱃지(1~5위)가 표시되어야 한다.

현재 순위 계산 로직(`rankSlots`)이 **경쟁 순위(competition/standard ranking, 1224 방식)**를 사용하고 있어 다음 버그들이 발생한다:

1. **뱃지 누락 버그**: 1위 동률 슬롯이 6개 이상일 때, 다음 득표 그룹의 순위가 7위 이상으로 계산되어 뱃지가 표시되지 않는다
2. **폐지된 로직 존재**: 전원 동률 시 임박한 날짜 순 5개만 노출하는 로직이 코드에 남아 있으나 이 기능은 폐지됨
3. **0표 카드 노출**: 투표 수가 0인 슬롯이 리스트에 표시되고 있음

---

## 순위 뱃지 표시 규칙

| 컨텍스트      | 순위     | 동작                   |
| ------------- | -------- | ---------------------- |
| 리스트뷰 카드 | 1~5위    | 해당 순위 색 뱃지 노출 |
| 리스트뷰 카드 | 6위 이하 | 뱃지 없음, 카드만 노출 |
| 셀 상세 모달  | 1~5위    | 헤더에 해당 순위 뱃지  |
| 셀 상세 모달  | 6위 이하 | 뱃지 영역 공백         |

### 순위 계산 방식 — 밀집 순위(Dense Ranking)

- 득표 수가 동일한 슬롯들은 같은 **그룹**으로 묶음
- 그룹 순서(1번째 그룹=1위, 2번째 그룹=2위, …)가 표시 순위가 됨
- 1위 그룹에 슬롯이 몇 개 있든, 2번째 득표 그룹은 **2위**

> 현재 방식(경쟁 순위): 1위 슬롯 6개 → 다음 그룹 = 7위 → 뱃지 없음 ✗  
> 변경 후(밀집 순위): 1위 그룹 6개 → 다음 그룹 = 2위 → 뱃지 있음 ✓

### 동률 내 정렬 기준 (기존 유지)

- 미래 날짜 > 과거 날짜
- 동일 날짜 내: 날짜 오름차순(임박한 날짜 우선)
- 같은 날짜: 슬롯 인덱스 오름차순(이른 시간 우선)

### 전체 노출 정책

- 전원 동률인 경우에도 **모든 슬롯 노출** (5개 truncation 폐지)
- 투표 수 0인 슬롯은 리스트에서 **완전히 제외**

## User Scenarios & Testing

### User Story 1 - 동률 그룹 뱃지 정상 표시 (Priority: P1)

득표 수가 같은 슬롯이 여러 개여도, 그 다음 득표 그룹은 올바른 순위 뱃지를 받는다.

**Why this priority**: 가장 빈번히 발생하는 버그이며 순위 뱃지의 핵심 기능

**Independent Test**: 1위 동률 6개 + 2위 그룹이 있는 스냅샷을 렌더링하면, 2위 그룹 카드에 2위 뱃지가 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 6개 슬롯이 모두 5표로 동률이고 1개 슬롯이 3표, **When** VoteRankCardList가 렌더링되면, **Then** 5표 슬롯 6개는 1위 뱃지, 3표 슬롯은 2위 뱃지가 표시된다
2. **Given** 각 득표 수가 모두 다른 6개 슬롯(6,5,4,3,2,1표), **When** 렌더링되면, **Then** 1~5위 슬롯은 순위 뱃지 표시, 6위(1표) 슬롯은 뱃지 없이 카드만 노출된다

---

### User Story 2 - 전체 슬롯 노출 (Priority: P1)

전원 동률이어도 모든 슬롯이 화면에 표시된다.

**Why this priority**: 폐지된 로직이 여전히 데이터를 자르고 있어 정보 손실 발생

**Independent Test**: 7개 슬롯이 모두 동표인 스냅샷을 렌더링하면, 리스트에 7개 카드가 모두 노출되는지 확인

**Acceptance Scenarios**:

1. **Given** 7개 슬롯이 모두 동표(전원 동률), **When** VoteRankCardList가 렌더링되면, **Then** 7개 카드가 모두 표시되며 모두 1위 뱃지를 가진다
2. **Given** 10개 슬롯이 모두 동표, **When** 렌더링되면, **Then** 10개 카드 모두 표시

---

### User Story 3 - 0표 카드 미표시 (Priority: P2)

투표 수가 0인 시간 슬롯은 결과 리스트에 표시되지 않는다.

**Why this priority**: 0표 카드는 의미 있는 정보가 아니며, 화면을 불필요하게 채움

**Independent Test**: 3개 슬롯 중 1개가 0표인 스냅샷을 렌더링하면, 리스트에 2개 카드만 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 슬롯 A(5표), 슬롯 B(3표), 슬롯 C(0표)가 있을 때, **When** VoteRankCardList가 렌더링되면, **Then** A와 B만 표시되고 C는 보이지 않는다
2. **Given** 모든 슬롯이 0표인 경우, **When** 렌더링되면, **Then** 빈 상태(EmptyState)가 표시된다

---

### Edge Cases

- 1위 그룹 슬롯 수가 5개를 초과해도 2위 그룹은 정상적으로 2위 뱃지를 받는다
- 각 그룹이 동표인 경우, 정확히 5개 그룹까지는 뱃지를 받는다
- 6위 이상 그룹은 뱃지 없이 카드로만 노출된다
- 과거 날짜 슬롯은 동률 그룹 내에서 미래 날짜 슬롯보다 뒤에 정렬된다
- hasVoted=false 참여자는 투표 집계에서 제외된다

## Requirements

### Functional Requirements

- **FR-001**: 순위 계산은 **밀집 순위(dense ranking)** 방식을 사용해야 한다 — 그룹 순서가 곧 순위 (1번째 그룹=1위, 2번째 그룹=2위, …)
- **FR-002**: 전원 동률(all-tie) 시 5개 truncation 로직을 제거하고 **모든 슬롯을 노출**해야 한다
- **FR-003**: 투표 수가 0인 슬롯은 **결과 리스트에서 제외**해야 한다
- **FR-004**: 1~5위 그룹 슬롯에는 해당 순위 색 뱃지가 표시되어야 한다
- **FR-005**: 6위 이상 그룹 슬롯에는 뱃지가 표시되지 않아야 한다 (카드는 노출)
- **FR-006**: 동률 그룹 내 정렬 기준(미래>과거, 날짜 오름차순, 슬롯 인덱스 오름차순)은 기존 동작을 유지한다
- **FR-007**: `rankSlots`, `toRankedSlots` 단위 테스트를 새 동작 기준으로 업데이트해야 한다

### Key Entities

- **SlotGroup**: 동일한 득표 수를 가진 슬롯들의 묶음. 밀집 순위에서 하나의 rank를 공유함
- **RankedSlot**: 순위(rank), 뱃지 그룹(badgeGroup), 가시성이 결정된 최종 슬롯 데이터
- **RankBadgeGroup**: `rank1 | rank2-3 | rank4-5 | none` — rank 1~5를 뱃지 색상 그룹으로 매핑

---

## Success Criteria

### Measurable Outcomes

- **SC-001**: 1위 동률 슬롯이 N개(N≥2)일 때, 2번째 득표 그룹 슬롯에 항상 2위 뱃지가 표시된다
- **SC-002**: 전원 동률 7개 슬롯 스냅샷에서 7개 카드가 모두 렌더링된다 (5개 truncation 없음)
- **SC-003**: 0표 슬롯이 포함된 스냅샷에서 해당 슬롯 카드는 리스트에 나타나지 않는다
- **SC-004**: `rankSlots`, `toRankedSlots` 단위 테스트가 새 동작 기준으로 모두 통과한다

---

## Assumptions

- 셀 상세 모달의 뱃지 표시는 `slot.badgeGroup` 값을 기반으로 렌더링되므로, 순위 계산 로직 수정만으로 모달 동작도 자동 수정된다고 가정
- `isAllTie` 필드는 UI에서 참조 여부를 확인 후 제거 또는 계산 방식 변경

## Clarifications

### Session 2026-05-09

- Q: 동률 그룹의 순위 방식은? → A: 밀집 순위(dense ranking). 1위 그룹이 N개여도 다음 그룹은 2위
- Q: 전원 동률 시 5개 truncation 폐지? → A: 예, 전체 노출
- Q: 0표 슬롯 처리? → A: 리스트에서 완전히 미표시
